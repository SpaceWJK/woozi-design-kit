# 매크로스트럭처 31종 — 페이지 골격 어휘집

- **출처**: [Nutlope/hallmark](https://github.com/Nutlope/hallmark) — `skills/hallmark/references/macrostructures.md` + `macrostructures/01~21-*.md` (MIT License) — 상세 고지·델타 목록은 `ATTRIBUTION.md` 참조.
- **이식일**: 2026-08-13
- **용도**: UI 위임 브리프에서 "페이지 전체가 어떤 형태로 짜이는가"를 한 단어로 지정하는 구조 축.
  색 팔레트/무드 프리셋(별도 스킨 시스템, 이 저장소엔 미수록)이나 taste 다이얼(VAR/MOT/DEN — 변주/모션/밀도 강도)과는 **직교하는 축**이다.
  프리셋이 "어떤 옷을 입힐지", 다이얼이 "얼마나 강하게 입힐지"를 정한다면, 이 문서는 "몸의 골격을 어떤 모양으로 짤지"를 정한다.
  세 축은 서로 자유롭게 조합 가능 — 예: `macrostructure: Stat-Led` + `테마: 다크 미니멀` + `MOT: 6`.
  본 저장소는 구조 축(macrostructure)만 제공한다 — 색/무드 축(프리셋)은 별도로 준비해야 한다(taste는 프리셋 없이도 기본 다이얼로 완전히 동작).
- **번역/서술 방식**: 21종 각각의 한국어 명칭·설명은 원문 직역이 아니라 우리 브리프에서 바로 쓸 수 있는 용어로 재서술했다. 원문 인용구는 참고용으로만 병기.

## 1. Bento Grid — 벤토 그리드

크기가 들쭉날쭉한 8~15개 블록(1×1~2×2 스팬 혼합)을 비정형 그리드에 배치해, 균일함이 아니라 크기 차이 자체로 리듬을 만드는 구조. 헤어라인 구분선 없이 12~24px 간격만으로 블록을 나눈다.

- **적합 용도**: 랜딩 페이지, 기능 소개 섹션, 대시보드 — 여러 콘텐츠가 동등한 비중으로 나열되어야 할 때
- **피할 때**: 메시지가 단 하나로 수렴해야 하는 페이지 (→ Marquee Hero, Stat-Led가 낫다)

## 2. Long Document — 롱 다큐먼트

마케팅용 구획 나누기 없이, 연속된 산문 안에 인라인 섹션 제목만 박아 넣는 구조. 제품을 광고가 아니라 한 편의 글처럼 읽게 만든다.

- **적합 용도**: 창업자 소개글, 브랜드 철학 문서, 심층 제품 설명

## 3. Marquee Hero — 마퀴 히어로

"히어로가 곧 페이지"인 구조 — 뷰포트 전체를 채우는 단 하나의 굵은 선언 또는 비주얼이 첫 화면의 전부다. 스크롤 없이도 메시지가 완결된다.

- **적합 용도**: 캠페인 티저, 단일 메시지 랜딩, 이벤트 페이지

## 4. Stat-Led — 스탯 리드

거대한 숫자 하나가 서사의 중심이 되고, 나머지 콘텐츠는 그 숫자를 뒷받침하거나 맥락을 붙이는 역할만 한다. 숫자는 반드시 설명 문구와 함께 등장해야 하며, 방어할 수 있는 진짜 지표가 없다면 사용하지 않는다("가짜 큰 숫자는 숫자가 없는 것보다 나쁘다").

- **적합 용도**: B2B/엔터프라이즈 성과 페이지, 펀드레이징, 임팩트 리포트

## 5. Workbench — 워크벤치

프레임에 담긴 제품 스크린샷이 주 콘텐츠이고, 카피는 최소화된 채 "사용법을 안내하는 투어"처럼 구성된다. 마케팅보다 사용성 증명에 가깝다.

- **적합 용도**: 제품 데모, SaaS 기능 페이지, 온보딩 가이드

## 6. Conversational FAQ — 대화형 FAQ

굵은 질문과 짧은 답변을 짝지어, 아코디언으로 접고 펼치는 정직한 인터뷰 톤을 낸다.

- **적합 용도**: 지원 문서, FAQ 섹션, 요금제 페이지 하단

## 7. Manifesto — 매니페스토

논쟁적인 대형 타이포(회전된 굵은 헤드라인, `-2°~-4°` 기울임)로 "무엇을 사야 하는지"보다 "무엇을 믿어야 하는지"를 먼저 선언하는 구조. 이미지는 거의 없거나 흑백 한 장뿐. 구매 유도가 아니라 이념적 동조를 목표로 한다.

- **적합 용도**: 브랜드 리포지셔닝 발표, 사명 선언, 스튜디오 신념 페이지
- **피할 때**: 즉각적인 구매/가입이 목표인 트랜잭셔널 페이지

## 8. Photographic — 포토그래픽

각 폴드마다 하나의 대형 이미지가 지배하고, 텍스트는 작은 주석 역할만 한다.

- **적합 용도**: 브랜드 무드 소개, 비주얼 중심 포트폴리오, 감성적 랜딩

## 9. Quote-Led — 쿼트 리드

인용문과 출처 표기로 문을 열어, "빌려온 신뢰"를 히어로 요소로 쓰는 구조.

- **적합 용도**: 고객 후기 중심 페이지, 소셜 프루프 섹션, 테스티모니얼 랜딩

## 10. Specimen — 스페시먼

좌측 여백에 번호 라벨("01 — HELLO." 식)을 두고, 대형 세리프 디스플레이와 비대칭 컬럼, 헤어라인 룰, 타이포그래피 전용 CTA(화살표만, 박스 없음)로 구성되는 에디토리얼 구조.

- **적합 용도**: 타입 파운드리, 저널/에디토리얼 홈페이지, 스페시먼 시트
- **주의**: 브리프가 막연할 때의 기본 선택지로 쓰지 않는다 — 에디토리얼/저널/파운드리 맥락이 명시된 경우에만 사용

## 11. Catalogue — 카탈로그

동일 항목의 변주들을 균일한 그리드로 나열하는, 시각적 인벤토리 인덱스에 가까운 구조.

- **적합 용도**: 제품 목록 페이지, 아카이브, 작품 갤러리

## 12. Letter — 레터

1인칭 시점의 친밀한 편지글 구조. "친애하는 ○○에게" 식 인사로 열고, 첫 화면 안에는 버튼을 두지 않는다.

- **적합 용도**: 창업자 레터, 뉴스레터 랜딩, 개인 브랜드 소개

## 13. Index-First — 인덱스 퍼스트

페이지 자체가 링크 목록이 되어, 순수 내비게이션을 디자인으로 삼는 구조.

- **적합 용도**: 허브 페이지, 아카이브 인덱스, 사이트맵형 랜딩

## 14. Narrative Workflow — 내러티브 워크플로우

번호 매긴 단계들이 시간 순서에 따른 사용 스토리를 프로세스 타임라인처럼 풀어낸다.

- **적합 용도**: 온보딩 플로우, "이용 방법" 섹션, 프로세스 설명 페이지

## 15. Split Studio — 스플릿 스튜디오

화면을 둘로 나누는 딥티크(diptych) 레이아웃이 매 블록마다 반복되며, 분할 방향이 페이지를 내려갈수록 좌우로 교대한다.

- **적합 용도**: 스튜디오/에이전시 소개, 비교(Before/After) 레이아웃, 포트폴리오

## 16. Feature Stack — 피처 스택

좌측은 스크롤에 고정(sticky)된 텍스트 패널, 우측은 스크롤에 연동되어 스크린샷이 영화적 시퀀스로 순환하는 패널로 구성.

- **적합 용도**: 기능 소개 페이지, 제품 스토리텔링, 스크롤형 데모

## 17. Type Specimen — 타입 스페시먼

서체 그 자체를 디자인의 주인공으로 세우는 구조. 커스텀 타이포그래피로 브랜드 정체성을 증명해야 하는 파운드리 홈페이지에 적합.

- **적합 용도**: 타입 파운드리, 브랜드 아이덴티티 쇼케이스

## 18. Portfolio Grid — 포트폴리오 그리드

필터링 가능한 프로젝트 카드 나열. 작업물 자체가 곧 제품인 스튜디오/디자이너용 구조.

- **적합 용도**: 포트폴리오 사이트, 스튜디오 작업물 아카이브, 필터형 갤러리

## 19. Map / Diagram — 맵/다이어그램

플로우차트, 평면도, 네트워크 그래프처럼 정보를 선형 서술이 아니라 공간적 배치로 조직하는 구조. 섹션 구분 없이 하나의 통합된 다이어그램이 본문 전체를 대신한다.

- **적합 용도**: 시스템 개요, 아키텍처 설명, 조직도/프로세스맵
- **피할 때**: 순차적 설명이 더 적합한 콘텐츠를 억지로 공간화하지 않는다

## 20. Ecosystem Index — 에코시스템 인덱스

추천/최신/카테고리별/사람별 등 여러 발견 경로를 동시에 제공해, "발견하는 재미"와 브라우징 자체의 가치를 강조하는 구조.

- **적합 용도**: 마켓플레이스 홈, 커뮤니티 허브, 콘텐츠 디렉토리

## 21. Component Playground — 컴포넌트 플레이그라운드

코드와 미리보기가 나란히 배치된 인터랙티브 블록이 주 콘텐츠. 복사-붙여넣기로 바로 쓸 수 있는 구현 방법을 보여주는 데 초점.

- **적합 용도**: 개발자 문서, 컴포넌트 라이브러리, 디자인 시스템 문서

## 증보 10종 (2026-08-14, 자체 설계 — 실무 앱 계열)

> 기존 21종은 랜딩/콘텐츠 페이지 중심이라 실무 앱·백오피스·커머스·문서 사이트 계열 골격이 비어 있었다. 아래 10종은 hallmark 이식분(1~21)과 달리 원본 출처 없이 이 세션에서 직접 설계했다 — 서술 형식(적합 용도/피할 때)은 기존과 동일하게 맞췄다.

## 22. Dashboard Shell — 대시보드 셸

좌측 고정 사이드바(내비게이션)와 상단 톱바(검색/프로필)가 프레임을 이루고, 그 안쪽에 KPI·차트 위젯이 카드 그리드로 배치되는 구조. 사이드바와 톱바는 스크롤에 고정되고 위젯 영역만 콘텐츠에 따라 늘어난다.

- **적합 용도**: 분석 대시보드, 관리자 콘솔, SaaS 백오피스 홈
- **피할 때**: 단일 메시지에 집중해야 하는 랜딩 페이지 (→ Marquee Hero, Stat-Led가 낫다)

## 23. Data Table Workspace — 데이터 테이블 워크스페이스

상단 필터/검색 바 아래 넓게 펼쳐진 대형 데이터 테이블이 주 콘텐츠이고, 행을 클릭하면 우측에서 상세 드로어가 슬라이드로 열리는 구조. 목록과 상세를 한 화면에서 오가야 하는 백오피스 작업에 최적화되어 있다.

- **적합 용도**: 백오피스 리스트 관리, CRM, 이슈/티켓 트래커
- **피할 때**: 항목 수가 적어 테이블 스캐폴딩(헤더/정렬/페이지네이션)이 과할 때

## 24. Kanban Board — 칸반 보드

가로로 나열된 상태 컬럼(3~5개, 컬럼마다 헤더+카운트)과 그 안에 세로로 쌓인 드래그 가능한 카드로 구성되는 구조. 카드의 위치(어느 컬럼의 몇 번째)가 곧 상태를 의미한다.

- **적합 용도**: 업무/이슈 관리 보드, 프로젝트 진행 현황, 워크플로우 시각화
- **피할 때**: 상태 전이 개념이 없는 콘텐츠 (단순 목록이면 Data Table Workspace가 낫다)

## 25. Commerce Showcase — 커머스 쇼케이스

좌측 대형 이미지 갤러리(메인 이미지+썸네일)와 우측 구매 패널(가격·옵션·CTA)이 2컬럼으로 짝을 이루는 구조. 단일 상품에 집중해 구매 결정을 끌어내는 것이 목적이다.

- **적합 용도**: 제품 상세 페이지, 단일 SKU 랜딩, 크라우드펀딩 상품 페이지
- **피할 때**: 여러 상품을 동시에 나열/비교해야 하는 목록형 페이지 (→ Storefront Grid가 낫다)

## 26. Storefront Grid — 스토어프론트 그리드

좌측 고정 필터 사이드바(카테고리·가격·속성 체크박스)와 우측 상품 카드 균일 그리드로 구성되는 구조. 탐색(필터링)과 훑어보기(그리드)를 한 화면에서 동시에 지원한다.

- **적합 용도**: 커머스 카테고리 페이지, 검색 결과 목록, 마켓플레이스 리스팅
- **피할 때**: 상품 수가 적어 필터 사이드바가 휑해 보일 때

## 27. Docs Portal — 독스 포털

좌측 접이식 내비게이션 트리, 중앙 본문(제목+단락+코드블록), 우측 "이 페이지에서" TOC로 이뤄진 3컬럼 구조. 깊은 위계의 문서를 잃지 않고 탐색하도록 설계된 정보 구조다.

- **적합 용도**: 기술 문서 사이트, API 레퍼런스, 지식베이스
- **피할 때**: 문서 위계가 얕아(1~2단계) 트리 내비게이션이 과할 때

## 28. Settings Console — 설정 콘솔

좌측 세로 섹션 내비(계정/보안/알림 등)와 우측에 세로로 쌓인 폼 그룹 스택(그룹마다 라벨+입력+저장 버튼)으로 구성되는 구조. 한 번에 한 섹션만 보여줘 설정 항목이 많아도 압도되지 않게 한다.

- **적합 용도**: 계정 설정, 관리자 환경설정, 프로필/조직 관리 페이지
- **피할 때**: 설정 항목이 5개 미만으로 적어 섹션 내비 자체가 불필요할 때

## 29. Chat Workspace — 챗 워크스페이스

좌측 대화 목록 패널(아바타+마지막 메시지 미리보기)과 우측 넓은 스레드 뷰(교대 배치 말풍선+하단 입력창)로 구성되는 구조. 여러 대화를 오가면서도 현재 스레드에 집중할 수 있게 한다.

- **적합 용도**: 메신저 UI, AI 챗봇 인터페이스, 고객지원 채팅 콘솔
- **피할 때**: 단일 대화만 존재해 목록 패널이 무의미할 때 (→ 전체 화면 스레드 뷰가 낫다)

## 30. Auth Onboarding — 인증 온보딩

화면 중앙에 고정폭 카드 하나만 떠 있고, 그 안에 스텝 인디케이터·폼 필드·주 CTA 버튼이 단일 컬럼으로 쌓이는 구조. 주의를 분산시키는 내비게이션이나 사이드바 없이 완료해야 할 단 하나의 동작에만 집중시킨다.

- **적합 용도**: 로그인/회원가입, 멀티스텝 온보딩, 비밀번호 재설정
- **피할 때**: 여러 정보를 동시에 비교/탐색해야 하는 페이지

## 31. Pricing Compare — 프라이싱 비교

상단에 나열된 플랜 컬럼(가격 강조, 추천 플랜은 시각적으로 돌출)과 그 아래 기능 매트릭스(행=기능, 열=플랜), 하단 FAQ 아코디언으로 이어지는 구조. 플랜 간 차이를 스캔 한 번으로 비교하게 만드는 것이 목적이다.

- **적합 용도**: 요금제 페이지, 플랜 비교 랜딩, 구독 업그레이드 유도 페이지
- **피할 때**: 플랜이 1개뿐이라 비교할 대상이 없을 때

## 브리프 사용 예시

1. `macrostructure: Stat-Led로, 테마: 손그림 스티커 콜라주 무드`
   → 방어 가능한 핵심 지표(예: "연간 비용 30% 절감")를 크게 내세우는 리포트에, 스티커 콜라주 무드의 손맛을 얹은 조합. 진지한 숫자 + 가벼운 톤의 대비.

2. `macrostructure: Bento Grid로, 테마: SaaS 대시보드 계열의 차분하고 정제된 톤`
   → 여러 기능을 동등한 비중으로 나열하는 대시보드/기능소개 페이지에, 차분하고 정제된 톤을 적용. 기능 카드마다 크기 차이로 우선순위를 암시.
