# 사용 가이드

이 문서는 `gallery/index.html`에서 구조 골격을 고르는 것부터, `taste` 스킬로 실제 UI를 생성하고
채점 결과를 확인하는 것까지 한 세션 안에 끝나는 흐름을 보여준다. 새 기능을 설명하는 문서가 아니라,
`skills/taste/SKILL.md`가 이미 구현하고 있는 동작을 사용자 여정 순서로 재배열한 것이다.

## 1. 설치

1. `skills/taste/`를 프로젝트의 `.claude/skills/`에 복사한다.
2. (선택) `macrostructures/`는 그대로 저장소 루트 아무 곳에나 두고 taste가 상대 경로로
   참조하게 한다 — 기본값은 `skills/taste/`와 같은 저장소 루트에 있다고 가정한다.
3. (선택) [StyleSeed](https://github.com/bitjaru/styleseed)를 프로젝트에 `design-rules/`로
   두면 Golden Rules·색 팔레트 프리셋과 연동된다. 없어도 taste는 기본 다이얼로 완전히 동작한다
   (그래서 "선택"이다 — 자세한 내용은 `skills/taste/SKILL.md`의 PHASE 0 참고).

## 2. 핵심 워크스루 — "갤러리에서 골격 고르기 → 스니펫 복사 → 생성 → 채점 확인"

1. `gallery/index.html`을 브라우저로 연다(더블클릭으로 바로 열리며, 서버가 없어도 동작한다.
   `gallery/gallery-data.js`가 데이터를 이미 인라인으로 담고 있기 때문). GitHub Pages 등에
   배포한 경우 그 URL을 열어도 동일하게 동작한다.
2. 31개 카드 중 콘텐츠 성격에 맞는 것을 찾는다 — 검색창(이름/설명/태그), 태그 다중 선택,
   가나다순 정렬로 좁힐 수 있다.
3. 카드를 클릭하면 설명·피할 때·데모(새 탭/인라인 미리보기)·`/taste --macro=<id>` 호출
   스니펫이 뜬다. 스니펫을 복사한다.
4. 실제 프로젝트에서 `/taste "설명" --macro=<id> [--var=N --mot=N --den=N]`을 실행한다.
5. taste의 자동 채점(Design quality/Originality/Craft/Functionality 4기준)이 실행되고,
   종합 점수가 7.0 미만이면 최대 2회까지 자동 재작업 루프가 돈다 — 결과 로그에서 어떤 기준이
   감점됐는지 확인할 수 있다.

## 3. 실전 예제 — 가상 랜딩 페이지 전 과정

**시나리오**: "1인 개발자의 사이드 프로젝트를 소개하는 랜딩 페이지를 만들고 싶다."

- **Step 1 — 갤러리에서 비교**: `Marquee Hero`(단일 메시지에 집중, 스크롤 없이 완결)와
  `Feature Stack`(좌측 고정 텍스트 + 우측 스크롤 스크린샷 시퀀스)을 열어본다. 이 프로젝트는
  기능이 3~4개라 스토리텔링이 필요하다고 판단해 `Feature Stack`을 선택한다 — 갤러리 카드의
  "적합 용도"(기능 소개 페이지/제품 스토리텔링/스크롤형 데모)가 이 판단의 근거다.
- **Step 2 — 스니펫 확인**: 카드 상세에서 `/taste "설명" --macro=feature-stack`을 복사한다.
- **Step 3 — 실행**:
  ```
  /taste "1인 개발자 사이드 프로젝트 랜딩, 미니멀" --macro=feature-stack
  ```
  taste는 프롬프트의 "미니멀" 키워드로 다이얼을 `VAR=3 MOT=4 DEN=3` 근처로 자동 추론하고,
  `feature-stack` 골격의 섹션 구성(sticky 텍스트 패널 + 스크롤 연동 스크린샷)을 뼈대로 사용한다.
  출력에는 "🎛️ 다이얼 제안" 블록과 선택된 컨셉 카탈로그 앵커(해당된다면)가 함께 표시된다.
- **Step 4 — 결과 확인**: 생성된 컴포넌트 코드와 함께 4기준 채점표가 출력된다. 시각 iterate가
  가능한 환경(dev server + Claude Browser 계열 MCP)이면 스크린샷도 함께 나온다.
- **Step 5 — 재작업 경로**: 종합 점수가 7.0 미만이면 "재작업 사이클 1/2 — {감점 기준} 재조정
  중" 로그와 함께 자동 수정이 시도된다. 2회 후에도 미달이면 "수동 검토 필요" 안내와 함께
  사용자에게 승인 여부를 묻는다 — 이때 그대로 승인할 수도, 수동으로 고칠 수도 있다.

## 4. `--macro`와 `--style` 조합

`--macro`(구조 골격, 이 저장소 동봉)와 `--style`(색/무드 프리셋, 별도 시스템 — 이 저장소엔
미수록)은 서로 직교하는 축이라 자유롭게 조합할 수 있다. 특정 프리셋 id 대신 카테고리로
예를 들면:

| 구조 골격 | 어울리는 무드 카테고리(예시) | 근거 |
|---|---|---|
| `stat-led` | 진지한 숫자 + 손맛 있는 콜라주 무드 | 방어 가능한 핵심 지표와 가벼운 톤의 대비가 리포트를 덜 딱딱하게 만든다 |
| `bento-grid` | SaaS 대시보드 계열의 차분하고 정제된 톤 | 여러 기능을 동등한 비중으로 나열할 때 톤까지 튀면 산만해진다 |
| `dashboard-shell` | 뉴트럴 베이스 + 단일 악센트 | 데이터 밀집 화면일수록 색이 적어야 정보 위계가 산다 |
| `marquee-hero` | 럭셔리/미니멀 계열 극단적 여백 | 단일 메시지 구조는 여백 자체가 메시지의 무게를 만든다 |

`--style` 프리셋 시스템이 없다면 이 표를 참고해 브리프에 "톤: ○○" 문구만 직접 써도 taste가
컨셉별 레퍼런스 카탈로그(SKILL.md 참고)로 다이얼을 추론한다.

## 5. FAQ / 트러블슈팅

**Q. `design-rules/`(StyleSeed)를 설치하지 않았는데 동작하나요?**
A. 그렇다. PHASE 0 §5가 "없음: 기본 AI Tells만 적용" 경고 1줄을 출력하고 그대로 진행한다.
Golden Rules 체크리스트만 스킵될 뿐 나머지 게이트(WCAG, 접근성, 레이아웃 견고성 등)는
동일하게 적용된다.

**Q. `--macro`에 존재하지 않는 id를 입력하면?**
A. 경고 1줄을 출력하고 macro 없이 진행한다(graceful fallback) — 프롬프트 키워드 기반 자동
추론 다이얼로 대체된다.

**Q. 시각 iterate(스크린샷 기반 자가 채점)를 지원하는 브라우저 자동화 도구가 없는 환경에서는?**
A. "시각 iterate 스킵" 로그와 함께 코드 레벨 채점(AI Tells grep + Golden Rules 체크리스트)만
수행한다 — 완전히 막히지 않고 결과는 나온다.

**Q. 데모 HTML(`macrostructures/demos/*.html`)을 그대로 내 프로젝트에 복사해도 되나요?**
A. 그렇다. 데모는 순수 인라인 CSS/SVG/바닐라 JS로만 구성되어 외부 의존이 없다 — 골격을
확인하는 참고 자료이자, 그대로 시작점으로 써도 되는 완결형 예시다.
